# AgentOS — инструкция для агента

Ты работаешь в репозитории с **AgentOS**: системой, которая помнит состояние
работы между сессиями и доводит задачи до конца, даже когда сессия
обрывается или кончаются лимиты токенов.

Этот файл — твой контракт. Человек не должен объяснять тебе, где вы
остановились: это знает система.

## 1. Первое, что делаешь в каждой сессии

```bash
agentctl resume --announce
```

Одна строка ответа скажет: есть ли незавершённые миссии, сколько задач
сделано, чего система ждёт и когда продолжит сама. Если работа есть —
продолжай её, не спрашивая человека «что дальше».

Если команда не найдена, окружение ещё не собрано:

```bash
make bootstrap && make doctor
```

## 2. Когда человек ставит новую задачу

Формулировка может быть сколь угодно абстрактной — разбирать её на шаги
твоя работа, не его.

```bash
agentctl goal "то, что попросил человек"
```

Система сама: зафиксирует критерии приёмки, построит план из задач,
подберёт роли субагентов и выдаст тебе задания. Уточняющий вопрос задавай
только если без ответа работа пойдёт заведомо не туда, и не больше двух за
миссию.

## 3. Как выполнять задания

После `goal` или `resume` ты получаешь список заданий с путями к брифам:

```
Задания субагентам (выполни каждое и верни результат):
  t_ab12cd34: Собрать вводные: ...
    бриф: var/runs/<mission>/briefs/t_ab12cd34.md
```

Для каждого задания:

1. Прочитай бриф. В нём цель, критерии приёмки, срез памяти проекта,
   доступные навыки и формат ответа.
2. Выполни его — своим механизмом субагентов, если он у тебя есть
   (в Claude Code это Task-субагенты; описания ролей лежат в
   `.claude/agents/agentos-*.md`). Независимые задания запускай параллельно.
3. Верни результат:

```bash
agentctl task report t_ab12cd34 --json '{"summary":"…","findings":[],"next_steps":[]}'
```

**Возвращай отчёт, а не транскрипт.** Ограничение в брифе (обычно 1200
токенов) — не пожелание: на нём держится вся экономия контекста.

Если задание уперлось в стену:

```bash
agentctl task block t_ab12cd34 --reason quota                      # кончились лимиты
agentctl task block t_ab12cd34 --reason capability --detail "нужен GITHUB_TOKEN"
agentctl task block t_ab12cd34 --reason approval  --detail "нужен git push"
```

Заблокированная задача не останавливает остальные ветки плана, а по квоте
продолжится сама после сброса лимитов.

После каждой порции отчётов снова вызывай `agentctl resume` — он выдаст
следующие задания или прогонит проверку результата.

## 4. Что делает система за тебя

| Что | Как это выглядит |
|---|---|
| Помнит знания проекта | `agentctl memory search "запрос"` — факты, уроки, решения |
| Помнит навыки | `agentctl skill list`, тело — `agentctl skill show <имя>` |
| Считает токены и деньги | `agentctl status` — расход и остаток бюджета |
| Переживает обрыв сессии | чекпоинты в `var/runs/`, указатель в `var/resume.json` |
| Ждёт сброса лимитов | задача в `BLOCKED_QUOTA` с точным временем продолжения |
| Проверяет результат | `agentctl verify <mission>` — гейты + критик по критериям |
| Подключает возможности | `agentctl capability request mcp github --reason "нужны PR"` |

## 5. Правила, которые нельзя нарушать

1. **Красный программный гейт — это отказ.** Его не переспорить и не
   отключить: тест не помечается skip, линтер не глушится, `allow_binaries`
   в политике не расширяется ради «чтобы прошло».
2. **Не объявляй «готово» до проверки.** Готово — это когда
   `agentctl verify` дал `accept`, а не когда тебе так кажется.
3. **Не работай мимо системы.** Результат, не отданный через
   `agentctl task report`, потеряется при обрыве сессии — как будто его не было.
4. **Не проси человека о том, что можешь узнать сам** — из репозитория,
   памяти или запуска команды.
5. **Секреты не попадают в код, БД и логи.** Нужен ключ — блокируй задачу с
   `--reason capability` и назови переменную окружения.

## 6. Где что лежит

```
config/agentos.yaml     бюджеты, режимы, квоты, самопроверка
config/models.yaml      каталог моделей по тирам и ценам
config/policy.yaml      что разрешено, что требует человека
config/agents/*.yaml    роли субагентов — правятся здесь, не в коде
config/mcp.json         каталог MCP-серверов
skills/<имя>/SKILL.md   навыки; в контекст идут только заголовки
docs/                   архитектура, сценарии, реализация, верификация
var/                    состояние: БД, журнал, чекпоинты, артефакты
```

Полное описание системы — `docs/ARCHITECTURE.md`.
Как всё проверяется — `docs/VERIFICATION.md`.
