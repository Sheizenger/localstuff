# Горизонт — приложение для Mac и iPhone

Нативное приложение (SwiftUI + Swift Charts) для учёта личных финансов с автоматическим
расчётом **горизонта накоплений**: сколько остаётся месяц к месяцу, когда лимит свободных
трат уходит в красную зону и через сколько при таком темпе закроется каждая цель.

Всё локально: данные лежат в одном JSON-файле на устройстве, никаких аккаунтов и сети.

Начиналось как приложение только для Mac; в v2 та же логика и почти все экраны переехали
в общие библиотеки, а поверх них появилась версия для iPhone (`HorizonMobile`) — с
вкладками вместо сайдбара и без единого AppKit-вызова в общем коде.

## Сборка (Mac)

Нужны инструменты командной строки Apple (Xcode или `xcode-select --install`), macOS 13 и новее.

```bash
cd HorizonFinance
./build_app.sh --install --run
```

Скрипт соберёт релизную версию, упакует `Горизонт.app` с иконкой, подпишет ad-hoc подписью,
положит в `/Applications` и запустит. Без флагов бандл остаётся в `build/`.

Во время разработки удобнее так:

```bash
swift run Horizon              # запустить окно
swift run Horizon --self-check # прогнать проверки расчётов и выйти
```

## Запуск на iPhone

Отдельного `.xcodeproj` не нужно — Xcode умеет запускать executable-таргеты SPM-пакета
с платформой iOS напрямую:

1. Откройте `Package.swift` в Xcode (`open Package.swift` или через «Open» в самом Xcode).
2. В переключателе схемы (рядом с кнопкой Run) выберите схему **HorizonMobile**.
3. Там же выберите симулятор iPhone (или подключённое устройство).
4. Нажмите Run (⌘R).

Приложение — обычный `TabView` с пятью вкладками (те же разделы, что и на Mac: Обзор,
Операции, Цели, Аналитика, Настройки), каждая в своём `NavigationStack`. Данные хранятся
в `Application Support` песочницы приложения на устройстве/симуляторе, отдельно от Mac-версии.

## Как это устроено

Приложение опирается на одну идею: **накопления — это решение до трат, а не остаток в конце месяца.**

Поэтому расходы делятся на два вида:

| Вид | Что это | Как влияет |
|---|---|---|
| Обязательные | аренда, счета, продукты, транспорт, документы | не трогают лимит, учитываются в темпе |
| Свободные | кафе, покупки, обустройство, поездки, подписки | тратят месячный лимит и красят индикатор |

**Темп накоплений** — доход минус все расходы за завершённые месяцы. Текущий, ещё не прожитый
месяц в расчёт не берётся: иначе прогноз скакал бы каждый день. Способ расчёта выбирается
в настройках:

- по последнему месяцу;
- среднее за 3 или 6 месяцев;
- взвешенный (свежие месяцы весят больше — веса 3:2:1);
- вручную.

**Горизонт цели** = остаток до цели ÷ месячный взнос. Взнос зависит от режима распределения:

- *по очереди* — весь темп идёт в верхнюю цель, следующая стартует после её закрытия
  (в карточке видно, через сколько цель вообще начнёт финансироваться);
- *параллельно, долями* — каждая цель получает свою долю темпа; если доли в сумме дают
  больше 100%, они нормируются.

Если у цели указан желаемый срок, приложение считает нужный ежемесячный взнос и показывает
зелёную / жёлтую / красную метку: успеваем, впритык или опаздываем.

## Красная зона

Индикатор запаса свободных трат учитывает не только сумму, но и то, какая часть месяца прошла:

- **зелёная** — расход в графике, показывает дневной остаток;
- **жёлтая** — либо запаса меньше трети, либо прогноз на конец месяца выходит за лимит;
- **красная** — запаса меньше 15% или лимит уже исчерпан.

Прогноз конца месяца рисуется отдельной риской прямо на полосе лимита.

## Разделы

- **Обзор** — свободные деньги, капитал, запас месяца, темп против плана, ближайшие цели.
- **Операции** — помесячный список доходов, расходов и переводов в цели, поиск, быстрый ввод.
- **Цели** — карточки со сроком и датой достижения, лента достижения целей во времени.
- **Аналитика** — доходы/расходы по месяцам, кривая капитала с пунктиром прогноза,
  норма сбережений, разбивка по категориям, таблица по месяцам.
- **Настройки** — валюта, план месяца, способ расчёта темпа, категории, экспорт/импорт данных.

Горячие клавиши: `⌘N` — операция, `⇧⌘N` — цель, `⌘1…⌘5` — разделы, `⌘S` — сохранить сразу.

## Данные

На Mac: `~/Library/Application Support/Horizon/horizon-data.json`.
На iPhone: тот же файл, но в песочнице приложения (`Application Support` контейнера
`HorizonMobile`) — Mac- и iOS-версии не делят данные между собой.

Сохранение автоматическое (с небольшой задержкой после изменения; на iPhone дополнительно
сохраняется при уходе в фон, так как `onDisappear` там ненадёжен). В настройках есть
экспорт и импорт (кроссплатформенные `.fileExporter`/`.fileImporter`, без `NSSavePanel`),
демо-данные и полный сброс. Если файл окажется повреждён, он не удаляется, а откладывается
рядом с пометкой `broken`.

## Структура кода

Пакет собирает четыре таргета: две библиотеки с общим кодом и два исполняемых приложения
поверх них.

```
Sources/HorizonCore/        библиотека: модель и расчёты, без единого импорта AppKit/UIKit
  Model/                     сущности, хранилище (Store), запись на диск, стартовые/демо-данные
  Logic/                     помесячная аналитика, зоны бюджета, прогноз по целям
  App/UIBus.swift            разделы приложения и общая шина для меню/модальных окон

Sources/HorizonUI/          библиотека: общие экраны и дизайн-система (чистый SwiftUI)
  Design/                    палитра, карточки, кольца прогресса, полосы лимита
  Views/                     пять разделов, модальные редакторы и настройки (общие для Mac и iPhone)

Sources/Horizon/             исполняемый таргет: приложение для Mac
  App/                       точка входа (AppKit, меню, горячие клавиши), самопроверка расчётов
  Views/RootView.swift       NavigationSplitView с сайдбаром

Sources/HorizonMobile/       исполняемый таргет: приложение для iPhone
  App/                       точка входа (обычный SwiftUI-лайфцикл, без AppKit)
  Views/RootView.swift       TabView с пятью вкладками, каждая в своём NavigationStack

Tools/                       генератор иконки (чистый Python, без зависимостей)
```

Расчётная часть (`HorizonCore/Logic/`) не знает про интерфейс, поэтому её можно прогнать
одной командой на Mac-таргете: `swift run Horizon --self-check` — проверяются арифметика
месяцев, разделение трат, все режимы темпа, границы зон и оба режима распределения по целям.
