# Верификация

Система обещает три нетривиальные вещи: доводить абстрактную задачу до
результата, переживать исчерпание лимитов и обрыв сессии, и не выдавать
непроверенный результат за готовый. Каждое обещание закрыто тестом, который
падает, если обещание перестанет выполняться.

Всё запускается **без единого API-ключа и без сети**: провайдер подменяется
детерминированным mock, MCP-клиент разговаривает с настоящим локальным
сервером-заглушкой.

## Как запустить

```bash
make bootstrap     # окружение и зависимости
make doctor        # конфиги, ключи, политика, готовность гейтов
make test          # все уровни, кроме live
make eval          # эталонные миссии
make lint          # ruff
make typecheck     # mypy
```

Тесты с реальными ключами помечены `live` и по умолчанию не запускаются:

```bash
ANTHROPIC_API_KEY=... .venv/bin/python -m pytest -m live
```

## Уровни

### Модульные (`tests/unit/`)

| Что проверяется | Почему это важно |
|---|---|
| Все переходы машины состояний, включая недопустимые | Молчаливая порча состояния ломает resume необратимо |
| Идемпотентность задач и эксклюзивный захват в 4 потока | Иначе параллельные ветки выполняют одну задачу дважды |
| `dedupe_key` в леджере | Повторная запись после краха удвоила бы счётчик токенов |
| Резерв бюджета при распределении | Без резерва критику не на что проверить результат |
| Роутер: mock только по явному флагу, время сброса в ошибке | Выдуманный ответ не должен выглядеть как результат работы |
| Политика: запреты, каждая ступень пайпа, отсутствие оболочек в allowlist | `sh -c '...'` обошёл бы весь allowlist |
| Типы в `allow_binaries` | В YAML голое `true` — булево, и allowlist молча ломается |
| Память: дедупликация, метасимволы FTS5, ужатие брифа | Пользовательский текст в `MATCH` роняет запрос; цель нельзя срезать |
| Защита гейтов от рекурсии | `make test` → pytest → миссия → `make test` уходит в бесконечность |

### Интеграционные (`tests/integration/`)

- **MCP** — настоящий обмен по протоколу с `tests/fixtures/echo_mcp_server.py`:
  `initialize` → `tools/list` → `tools/call`, включая ветку `isError` и
  случаи «нет бинаря» и «нет секрета».
- **Возможности** — `auto:true` подключается сам; `auto:false`, отсутствие в
  каталоге и нехватка секрета дают понятный запрос человеку, а не тупик.
- **Память в связке** — знание, добытое одной миссией, доезжает до брифа
  следующей задачи; черновик навыка не активен, пока его не продвинули.
- **Генератор `.claude/agents`** — файл на каждую `selectable` роль, роли
  системы (оркестратор, критик) наружу не выставляются.
- **CLI отдельными процессами** — `init` → `goal` → `task report` → `resume`
  → `status`, коды выхода и текст, который читает агент-хост.

### Приёмка (`tests/e2e/test_acceptance_gate.py`)

Регрессия на найденный дефект: миссия закрывалась как `DONE` с
неподтверждёнными критериями, потому что вердикт критика перезаписывался
пересчётом статуса по задачам. Закреплено: миссия висит в `BLOCKED`, пока
критерии не подтверждены; вердикт агент-хоста закрывает её; красный гейт
отменяет даже вердикт хоста; проваленная задача даёт `FAILED`, а не `DONE`.

### Человек в контуре (`tests/integration/test_human_in_the_loop.py`)

Запрос на подтверждение попадает в очередь `approvals` автоматически при
блокировке задачи, не дублируется при повторных попытках, а решение
возвращает задачу в очередь исполнения или проваливает её. Отдельно —
поднятие исчерпанного бюджета и снятие миссии с паузы.

### Сквозные (`tests/e2e/`)

1. **Обычная миссия.** Абстрактная цель раскладывается минимум на три
   задачи разных ролей, критерии приёмки фиксируются до работы, расход
   учитывается и не выходит за бюджет, чекпоинт и указатель resume пишутся.
2. **Исчерпание лимита.** Mock отдаёт `QuotaExhausted` на конкретном вызове.
   Задача уходит в `BLOCKED_QUOTA` с временем сброса, **другие ветки
   продолжают идти**, `resume` после ожидания доводит миссию. Отдельно
   проверяется, что объявление на старте сессии — одна строка и содержит
   срок продолжения.
3. **Краш.** Дочерний процесс начинает миссию и убивает себя `SIGKILL`
   посреди работы. Проверяется: база открывается, план сохранён, расход до
   краха учтён ровно один раз, `resume` не плодит дубликаты задач и не
   удваивает счётчик.

### Кросс-провайдерный контракт (`tests/test_provider_conformance.py`)

Один набор для всех адаптеров: конвертация сообщений и инструментов в
родной формат каждого API, разбор ответа, подсчёт usage и нормализация
ошибок. Отдельно проверено, что 429 «кончились деньги» превращается в
`QuotaExhausted` со временем сброса, а 429 «слишком часто» — в `RateLimited`:
на этом различии держится авто-resume. Без ключа адаптер обязан сказать об
этом исключением, а не вернуть пустой ответ.

### Эталонные миссии (`evals/`)

`agentctl eval run` прогоняет миссии из `evals/missions/*.yaml` в
изолированном состоянии и сверяет численные ожидания: сколько задач
выполнено, были ли провалы, не разросся ли расход токенов. Это защита от
регрессий самоулучшения: система правит собственные промпты и навыки, и ей
нужна неподвижная точка отсчёта.

## Ручная приёмка

```bash
make bootstrap && make doctor
agentctl goal "любая абстрактная задача"
agentctl status                    # что сделано, что блокирует, когда продолжит
# закрыть сессию и открыть новую:
agentctl resume --announce         # должен сам объявить, что подхватил работу
```

Признак, что всё работает как задумано: во второй сессии человеку не
пришлось объяснять, где остановились.

## CI

`.github/workflows/ci.yml` гоняет `ruff`, `mypy`, весь `pytest` и
`agentctl eval run` на чистой машине. Секреты не нужны — ни один тест не
ходит в сеть.
