# Быстрый старт: из любого чата, с нуля

Один раз копируете сообщение — дальше просто ставите задачи.
Чат может быть каким угодно: этот репозиторий, чужой проект, пустая папка.

---

## Шаг 1. Открыть чат и вставить это

Скопируйте целиком. Одно сообщение, ничего дописывать не нужно.

```
Поставь и используй AgentOS: https://github.com/Sheizenger/localstuff

Сделай ровно это:

1) uv tool install --force --reinstall "agentos @ git+https://github.com/Sheizenger/localstuff@claude/multi-agent-system-architecture-c1td12"
   (нет uv — curl -LsSf https://astral.sh/uv/install.sh | sh)
2) agentctl install
3) agentctl doctor
4) export AGENTOS_AGENT_ID=<короткое имя под мою задачу>
5) agentctl resume --announce

Дальше работай по контракту из AGENTS.md, который положила установка:
каждую мою задачу отдавай в agentctl goal, результаты возвращай через
agentctl task report, «готово» — только после agentctl verify.
Не пересказывай мне шаги, покажи результат.
```

Всё. Больше про AgentOS писать не нужно — следующим сообщением
пишете саму задачу.

> Ссылка указывает на ветку `claude/multi-agent-system-architecture-c1td12`:
> в `main` этого кода ещё нет. После вливания в `main` из ссылки убирается
> всё, что после `@`.

**Что произойдёт:** установится `agentctl`, в проекте появятся `AGENTS.md`,
`CLAUDE.md`, `.mcp.json` и настройки, а сам чат получит инструменты
`agentos_*` и контракт, по которому он обязан работать.

---

## Шаг 2. Дать задачу

Обычным сообщением, настолько абстрактно, насколько хотите:

```
Разберись, почему падает сборка, и почини.
```

Дальше агент делает всё сам: превращает задачу в критерии приёмки,
раскладывает её на план, раздаёт задания субагентам, запускает гейты,
проверяет результат и закрывает миссию, только когда критерии подтверждены.

---

## Шаг 3. Ничего не делать

Спрашивать «где результат» не нужно. Если хочется посмотреть:

```bash
agentctl status         # что сделано, что блокирует, когда продолжит
```

Кончились токены — работа встаёт в очередь с точным временем сброса и
продолжается сама. Оборвалась сессия — состояние на диске, а не в переписке:
новый чат подхватывает работу первой же командой `agentctl resume`.

Остановить: скажите об этом в чате. Это единственная причина, по которой
система прекращает доводить задачу до конца.

## Чтобы ничего не сломать на вашей машине

Агент выполняет команды. По умолчанию он ограничен политикой
(`allow_binaries`, запрет на запись вне проекта, подтверждение человека на
`git push`), но политика говорит, *что* запускать, и ничего не говорит о
*где*. Если этого мало — запускайте в контейнере: внутрь смонтированы ровно
два каталога, проект и общая память, остальная машина недостижима.

Добавьте в первое сообщение одну строку:

```
Всё запускай через agentctl sandbox, а не напрямую.
```

Тогда вместо `agentctl goal "…"` агент будет делать
`agentctl sandbox goal "…"`. Образ соберётся сам при первом запуске
(нужен Docker; `AGENTOS_DOCKER=podman` — если podman).

Полная изоляция от сети — `AGENTOS_NETWORK=none`, но тогда агент не сможет
ходить к API моделей и в git.

## Несколько задач одновременно

Мастер-агент — это чат. Их может быть сколько угодно, по чату на задачу,
в одном и том же проекте. Чтобы они не растаскивали работу друг друга,
каждый называет себя: это и есть строка `export AGENTOS_AGENT_ID=…` из
первого сообщения.

| Чат | Имя | Что видит |
|---|---|---|
| «релиз» | `AGENTOS_AGENT_ID=release` | только свои миссии |
| «баги» | `AGENTOS_AGENT_ID=bugfix` | только свои миссии |
| любой | `agentctl status --all` | все миссии проекта |

Забыли назваться — не страшно: все работают под общим агентом `default`,
и пока задача одна, разницы нет.

## Если что-то пошло не так

| Симптом | Что это значит | Что сделать |
|---|---|---|
| `agentctl: command not found` | инструмент не в PATH | `export PATH="$HOME/.local/bin:$PATH"` |
| `doctor` пишет «программных гейтов нет» | в проекте не нашлось команды тестов | впишите свои в `.agentos/config/agentos.yaml` |
| `doctor` пишет «гейт не запустится» | команды приёмки нет в PATH | поставьте её или поправьте гейт |
| «ни один провайдер не настроен» | нет API-ключей | это нормально: субагентов запускает сам чат |
| Обновление не доехало | uv переиспользовал старую сборку | ставьте с `--reinstall` |
| Агент отвечает сам, мимо AgentOS | не прочитал контракт | «работай через agentctl, как написано в AGENTS.md» |

## Что именно появится в вашем проекте

```
AGENTS.md                  контракт для агента — читают все хосты
CLAUDE.md / GEMINI.md      то же для своих хостов
.cursor/rules/agentos.mdc  правило для Cursor
.mcp.json                  регистрация MCP-сервера AgentOS
.claude/settings.json      хук: подхват работы на старте сессии
.agentos/config/           настройки этого проекта (коммитится)
.agentos/var/              состояние: база, журнал, чекпоинты (в .gitignore)
```

Установка идемпотентна и не трогает чужое: markdown правится между
маркерами, JSON сливается по ключам. Повторный запуск безопасен.

Codex настраивается глобально, поэтому одну строку для
`~/.codex/config.toml` установка покажет, но сама туда не полезет.
